# CLAUDE.md — working on SpendVeto

SpendVeto is the spend-governance layer for AI agents that pay for things (x402/USDC + MCP). Rails move the money; SpendVeto decides whether the agent is allowed to move it — before anything settles.

## The one rule that governs everything

**Every public claim must be an assertion in `npm run verify`.** The count in README/site/PITCH must equal what **a fresh clone** produces — `npm run verify 2>&1 | grep -c "^PASS"` (currently **272**), not what this machine produces. Three further assertions cover the real cross-project Basis integration and only run when `../prediction-copilot` sits alongside this repo, which takes a maintainer checkout to 275. Publish 272: a reviewer who clones and counts must never find the site claiming more than they can reproduce. New feature → new assertion(s) → bump the count everywhere it appears (grep for the old number across `README.md PITCH.md site/*.html launch/*.md`). Never ship a fake control: features that can't work locally yet are *declared slots that refuse honestly* (see `rails/index.js` roadmap rails), never stubs that pretend.

## Commands & ports

```bash
npm run server     # :8402 — API + the 10-page Console (dashboard/)
npm run site       # :8403 — static marketing site (site/ — self-contained, no CDNs)
npm run proxy      # :8404 — enforcement proxy (keyless agents POST intents)
npm run call -- <tool> [--child="label"] [--chain=id] [--dry-run]
npm run delegate -- <cap> [label] [--parent x] [--tools a,b] [--chains c1,c2] [--ttl 10m]
npm run policy [-- apply <pack>]
npm run mcp        # stdio MCP server — stdout must stay protocol-clean (dotenv quiet:true)
npm run verify     # 272 e2e assertions; takes 3–4 min (approval timeouts + TTL sleeps)
```

`SPENDVETO_MODE=simulate` (default, zero-setup, real ECDSA, local settlement) or `testnet` (real x402 v2; **facilitator-adaptive multichain** — the gate calls the facilitator's `GET /supported` at boot and registers every registry chain it names, one accepts entry per chain in every 402 with explicit per-chain USDC AssetAmounts (the `$` shorthand lacks defaults for ethereum/optimism/avalanche). Public facilitator = base-sepolia today; a CDP facilitator key + funded wallet flips its mainnets live with zero code changes. Rail id is `x402-live` (was x402-base-sepolia); `/api/chains` reports per-chain `settlement: live|ready|simulated`).

## Hard-won gotchas

- **Free the ports before `verify`, one port at a time**: `for p in 8401 8402 8404 8498 8499; do lsof -ti :$p | xargs kill -9 2>/dev/null; done` (8401 = the suite's testnet-mode server, 8498 = its mock facilitator). Multi-port `lsof -ti :8402 :8404` fails silently → a stale server keeps the port → verify's own server dies EADDRINUSE and the suite runs against old code with leftover in-memory state. The boot check now names EADDRINUSE explicitly.
- Verify wipes `data/{ledger,balances,delegations,children,freezes,waitlist}.json` at start and restores `data/policy.json` in `finally` — restart the demo servers and reseed after a run.
- Suite bookkeeping is exact: paid/blocked ledger counts and blocked-USD totals are asserted. Adding a test call means updating the counts in the stats/ledger assertions.
- Payment header is `address:nonce[:chain]:signature`; the chain is inside the signed message (`nonce:resource:price:chain`). Three-part headers settle on `base-sepolia` (legacy/raw-test compat).
- `data/children.json` holds child private keys (simulate demo money only) — gitignored, keep it that way. `.env.local` likewise.
- Shell cwd resets between tool calls — always `cd /Users/.../spendveto &&` or use absolute paths (a `rails/` dir once landed in `$HOME`).

## Map

`shared-config.js` tools + 7-chain registry · `rails/` one `pay()` contract (x402 live, AP2/ACP/MPP honest slots) · `client/policy.js` the governance wedge (structured denials: `code` + `suggestion`) · `client/pay.js` governed pipeline (policy → approval → rail; `withWalletLock` serializes it per wallet so concurrent calls can't race the same cap) · `server/simulate.js` 402 gate (chain-scoped sigs, signed receipts; **server-authoritative** — runs `checkPolicy` + consumes single-use approvals at the gate so a hand-rolled client can't bypass policy) · `server/ledger.js` hash-chained entries (`verifyLedgerChain` → `/api/ledger/verify-chain`, tamper-evident) · `server/shadow.js` shadow mode (candidate policy evaluated at the gate without enforcing → `/api/shadow` report; `checkPolicy` takes a policy-override param) · `client/policy.js` also enforces `allowedPayees` (global + per-delegation payee scope; codes `payee_not_allowed`/`payee_scope`) · `server/auth.js` API-key auth + roles (viewer<approver<admin; `requireAuth(minRole)` on 12 admin-surface endpoints; **open until the first key exists** or `SPENDVETO_REQUIRE_AUTH=1`; mint via `npm run apikey`) · `server/trust.js` cross-org trust graph (`/api/trust/graph` nodes+delegation edges+org sub-tree rollups; `/api/trust/payee/:addr` counterparty credit bureau; shared `trustScoreFor` also backs `/api/trust/:addr`) · `server/anomaly.js` burst auto-freeze **plus** `analyzeAnomalies` advisory panel (block-rate spike / novel payee / category drift / amount outlier → `/api/anomaly/:addr`; ledger entries carry `payTo`) · `server/events.js` decision events (`spendveto.decision.v1` schema over the ledger → `/api/events` + `/api/events/export` JSONL for SIEM; entries carry `policyHash` — `policyHash()` in client/policy.js, recursive sorted-key SHA-256 of the effective policy, stamped at the gate) · `server/billing.js` governed-billing sink (paid settlement → `spendveto.usage.v1` event to `policy.billingWebhookUrl`, optional HMAC, fire-and-forget like alerts) · `/api/ap2/evaluate` AP2-style mandate evaluation (full policy pipeline on an AP2-shaped mandate → verdict signed by the receipt key via `signDecision` in simulate.js; settlement stays a roadmap slot; `?format=vc` re-shapes the same signed verdict as a W3C-VC-shaped envelope via `server/vc.js` — own proof type, not a registered suite, but the embedded signature is the real one) · `server/consents.js` signed consent records for delegation grant/revoke (Visa-Trusted-Agent-style; `GET /api/consent/:delegationId`, `POST /api/consent/verify`), wired into both `/api/delegations` and `/api/delegations/wallet` · `/api/agentic-token` Mastercard-Agent-Pay-style bundle: a delegation scoped to exactly one merchant payee + its signed consent, one object · `server/receipts.js` `normalizeReceipt` — one shape for every rail's ledger entries (`GET /api/receipts/normalized`); `proof` only when the entry actually has one · `server/ap2.js` AP2 **mandate-chain** governance (`POST /api/ap2/mandate-chain`): checks the cart against the intent it claims to derive from — `cart_exceeds_intent`, `cart_total_mismatch` (declared total vs its own line items, checked *before* any cap), `merchant_drift`, `category_drift`, `multi_merchant_spray`, `intent_expired`, `cart_intent_mismatch` — then runs the normal policy pipeline; `reconcileHumanNotPresent` handles AP2 v0.2.0 human-not-present flows, where the signed intent's ceiling substitutes for the approval nobody can answer and anything beyond it fails closed (`hnp_no_authority`) · `server/discovery.js` x402 v2 **Bazaar** on both sides: `GET /api/discovery/resources` publishes the catalog in Bazaar's schema (CAIP-2 network, USDC base units, `x-spendveto.governed` flag), and `POST /api/discovery/govern` filters *someone else's* discovered catalog through the live policy before the agent ever sees it (price cap / payee allowlist / chain allowlist / category cap) — a pre-filter that shrinks what a compromised agent can name, never a replacement for the gate · `server/acp.js` ACP (OpenAI/Stripe) **Shared-Payment-Token scope** governance (`POST /api/acp/checkout`): the SPT is a bearer credential minted for an amount/merchant/window, and the merchant validates the token while nobody validates the shopping — so this checks the session against the token that funds it (`spt_merchant_drift`, `session_total_mismatch` checked *before* the ceiling, `session_exceeds_spt`, `spt_expired`, `spt_category_drift`, `spt_currency_mismatch` — never compares across currencies, `spt_session_mismatch`), then the normal policy pipeline · `server/integrity.js` **request integrity** — the only control that answers "is this the spend I *allowed*?" rather than "is this spend allowed?": canonical recursive sorted-key SHA-256 of the request, signed by the receipt key (`POST /api/integrity/bind` → `POST /api/integrity/verify`), single-use + TTL + agent-bound, so a payload swapped between decision and execution fails `request_integrity_mismatch` while every amount-based check still passes. Buyer-side counterpart to the security extension Fireblocks is contributing to x402. An allowed `/api/acp/checkout` returns a binding; a denial returns none · `server/disputes.js` **dispute evidence packs** (`GET /api/disputes/:entryHash/evidence`, `POST /api/disputes/verify`): agent purchases produce no device fingerprint, IP, or browsing session, so they lose chargebacks by default — this assembles what the ledger already holds (chain position + prev/next hash as the anti-backdating argument, policy hash at spend with drift disclosed, the human approval, the signed consents for the delegation) into one bundle signed over its own digest. Carries a `doesNotEstablish` list inside the artifact — it never implies delivery or satisfaction · `server/otel.js` **OpenTelemetry** decision spans (`GET /api/otel/spans`, OTLP/HTTP JSON, dependency-free — no OTel SDK in the component whose job is refusing to trust things): adopts an inbound W3C `traceparent` so a refusal lands inside the agent run that caused it, span ids derived from the entry hash so re-export doesn't duplicate, and **blocked ≠ ERROR** (a refusal is the gate working; colouring it red trains teams to ignore the colour that matters) · `server/index.js` all APIs (`/metrics` = Prometheus scrape target) · `proxy/` custody + idempotency keys + agent identities (`GET /proxy/agents/:id/credential` — KYA credential joining identity → wallet trust score/freeze/delegation scope; per-agent rate limiting + freeze independent of the wallet — `PER_AGENT_CALLS_PER_MIN`, `POST /proxy/agents/:id/freeze|unfreeze`) · `mcp/` stdio middleware · `sdk/` the npm client (`SpendVeto` class — pay/dryRun/chat/registerAgent) · `integrations/` framework adapters (`langchain.js`, `openai-agents.js`, `eliza.js` — all dependency-free; the OpenAI one reshapes the LangChain tools; the ElizaOS one returns a real Plugin with one Action per catalog tool **plus a budget Provider** that injects remaining spend into the agent's context *before* it picks a tool, because a refusal the model didn't see coming produces a retry loop instead of a cheaper choice) · `dashboard/` the Console · `site/` marketing (self-contained; wallet modal = EIP-6963, no WalletConnect SDK) · `launch/` Show HN, demo script, research prompts + triage · `PITCH.md` funding doc (every number cited) · `CONTROLS.md` control inventory mapped to EU AI Act / NIST AI RMF, every row citing its verify assertion.
